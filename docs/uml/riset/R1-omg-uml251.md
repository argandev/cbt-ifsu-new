# R1 — Riset Spesifikasi OMG UML 2.5.1 untuk Audit 7 Diagram CBT SMK v2

- **Dokumen acuan utama:** OMG Unified Modeling Language, Version 2.5.1,
  OMG Document Number **formal/2017-12-05**, Desember 2017
  (https://www.omg.org/spec/UML/2.5.1/PDF).
- **Peran dokumen ini:** daftar aturan KONKRET yang bisa dicek oleh tim audit.
  Setiap aturan mengutip bagian spesifikasi (nomor sub-klausul) dan status verifikasi.
- **Metode:** seluruh aturan di bawah dibaca langsung dari teks spesifikasi resmi OMG
  (PDF di URL di atas) pada 17 Okt 2026. Situs uml-diagrams.org TIDAK dipakai sebagai
  dasar aturan apa pun (hanya muncul di hasil pencarian, tidak dikutip).
  Dokumentasi StarUML TIDAK dipakai — tidak ada aturan di sini yang bersandar pada
  perilaku tool; StarUML adalah implementasi, bukan spesifikasi.
- **Konvensi status:**
  - `TERVERIFIKASI` = kalimat aturan ditemukan verbatim / hampir verbatim di spesifikasi.
  - `TIDAK TERVERIFIKASI` = aturan tidak ditemukan di teks spesifikasi yang diakses;
    JANGAN dipakai sebagai dasar temuan audit sampai ada bukti lain.
  - `KOREKSI PREMIS` = anggapan umum yang ternyata TIDAK sesuai spesifikasi.
- **Catatan:** file `docs/uml/cbt-smk-v2.mdj` TIDAK diubah dalam riset ini.

| ID | Aturan | Referensi spesifikasi | Status / Sumber |
|---|---|---|---|
| CF-01 | Notasi CombinedFragment: persegi panjang bergaris tepi solid; operator ditulis di pentagon (kompartemen kecil) di sudut kiri atas frame. Lebih dari satu operator di pentagon = singkatan untuk CombinedFragment bersarang. | §17.6.4.3; §17.6.4.6 | TERVERIFIKASI — OMG UML 2.5.1 |

| CF-03 | `alt` = pilihan perilaku: PALING BANYAK SATU operand dipilih. Operand terpilih HARUS punya guard eksplisit atau implisit yang bernilai true pada titik tersebut. Operand tanpa guard dianggap punya guard implisit `true`. | §17.6.3.7; §17.12.15.3 `alt` | TERVERIFIKASI — OMG UML 2.5.1 |
| CF-04 | Operand `alt` yang di-guard `else` berarti guard = negasi dari disjungsi semua guard lain di CombinedFragment yang sama. | §17.6.3.7 | TERVERIFIKASI — OMG UML 2.5.1 |
| CF-05 | `alt`: bila TIDAK ADA operand yang guard-nya true, maka TIDAK ADA operand yang dieksekusi dan sisa enclosing InteractionFragment yang dieksekusi. (Jadi `alt` tanpa operand `else` dan semua guard false adalah perilaku yang sah, bukan kesalahan.) | §17.6.3.7 | TERVERIFIKASI — OMG UML 2.5.1 |
| CF-06 | `opt` = pilihan perilaku dengan SATU operand: operand terjadi ATAU tidak terjadi sama sekali. Semantiknya setara `alt` dengan satu operand berisi + satu operand kosong. | §17.6.3.8; §17.12.15.3 `opt` | TERVERIFIKASI — OMG UML 2.5.1 |
| CF-07 | `break` = skenario pemutus: operand dijalankan SEBAGAI PENGGANTI sisa enclosing InteractionFragment. Guard true → break dipilih, sisa diabaikan. Guard false → break diabaikan, sisa dipilih. Tanpa guard → pilihan non-deterministik. **Break harus mencakup (cover) SEMUA Lifeline** yang dicakup enclosing InteractionFragment (constraint formal; §17.6.3.9 mengatakannya sebagai "should", constraint OCL §17.12.3.7 mengatakannya sebagai keharusan). | §17.6.3.9; §17.12.3.7 `break`; §17.12.15.3 `break` | TERVERIFIKASI — OMG UML 2.5.1 |
| CF-08 | `loop` = operand diulang sejumlah kali. Guard boleh memuat jumlah iterasi minimum (`minint`) dan maksimum (`maxint`) plus ekspresi Boolean. Loop beriterasi minimal `minint` kali dan maksimal `maxint` kali; setelah iterasi minimum tercapai dan ekspresi Boolean false, loop berhenti. Bila ada InteractionConstraint terpisah dengan spesifikasi, loop hanya berlanjut bila spesifikasi itu true — terlepas dari jumlah minimum. | §17.6.3.17 | TERVERIFIKASI — OMG UML 2.5.1 |
| CF-09 | Sintaks loop: `loop[(<minint>[, <maxint>])]`. `minint` = bilangan asli non-negatif; `maxint` = bilangan asli ≥ `minint`, atau `*` (tak terbatas). Hanya `minint` saja → `minint = maxint`. Hanya `loop` saja → batas bawah 0, batas atas tak terbatas. Constraint: `minint` ≥ 0; `maxint` > 0; bila `maxint` ada maka `minint` harus ada dan `maxint` ≥ `minint`. | §17.6.4.9; §17.12.12.5 `minint_non_negative`, `maxint_positive`, `maxint_greater_equal_minint` | TERVERIFIKASI — OMG UML 2.5.1 |
| CF-10 | Bila `interactionOperator` = `opt`, `loop`, `break`, `assert`, atau `neg`, CombinedFragment HARUS punya tepat SATU operand. (`alt` boleh banyak operand; CombinedFragment umum punya operand `[1..*]`.) | §17.12.3.7 `opt_loop_break_neg`; §17.12.3.6 | TERVERIFIKASI — OMG UML 2.5.1 |
| CF-11 | Penulisan guard (InteractionConstraint): `[` (ekspresi-Boolean \| `else`) `]`. Bila InteractionConstraint dihilangkan, diasumsikan `true`. Guard ditampilkan dalam kurung siku menutupi lifeline tempat event pertama akan terjadi, diposisikan di atas event itu, di dalam Interaction / InteractionOperand yang memuatnya. | §17.6.4.2; §17.12.12.1 | TERVERIFIKASI — OMG UML 2.5.1 |
| CF-12 | Guard operand: (a) HARUS ditempatkan tepat sebelum (di atas) OccurrenceSpecification yang akan menjadi OccurrenceSpecification pertama di dalam InteractionOperand itu; (b) hanya boleh merujuk nilai lokal Lifeline tempat guard berada, atau nilai global seluruh Interaction. | §17.12.14.5 `guard_directly_prior`, `guard_contain_references` | TERVERIFIKASI — OMG UML 2.5.1 |
| CF-13 | `minint` / `maxint` hanya boleh ada bila InteractionConstraint terkait dengan operand sebuah CombinedFragment `loop`. | §17.12.12.5 `minint_maxint` | TERVERIFIKASI — OMG UML 2.5.1 |

Ujung asosiasi yang dimiliki Class SELALU navigable; ujung yang dimiliki Association boleh navigable atau tidak. | §11.5.4 | TERVERIFIKASI — OMG UML 2.5.1 |
| CL-06 | Semantik navigability: ujung Property asosiasi yang dimiliki oleh Class ujungnya, atau yang merupakan `navigableOwnedEnd` dari Association, menandakan Association navigable dari ujung-ujung lawannya. Navigability berarti instance di ujung lawan dapat mengakses instance peserta secara efisien pada runtime. Bila ujung tidak navigable, akses dari ujung lain mungkin tetap bisa, tetapi mungkin tidak efisien. | §11.5.3.1 | TERVERIFIKASI — OMG UML 2.5.1 |
| CL-07 | Agregasi: `shared` = belah ketupat KOSONG di ujung garis asosiasi yang BERLAWANAN dengan ujung yang ditandai `shared`; `composite` = belah ketupat TERISI di ujung yang berlawanan dengan ujung `composite`. Ujung Property asosiasi hanya boleh ditandai agregasi shared/composite bila Association biner DAN ujung lainnya tidak ditandai shared/composite. | §11.5.4; §11.5.3.1 | TERVERIFIKASI — OMG UML 2.5.1 |
| CL-08 | `VisibilityKind`: `public` = terlihat semua elemen yang dapat mengakses isi Namespace pemilik; `private` = hanya terlihat di dalam Namespace pemilik; `protected` = terlihat oleh elemen yang punya relasi generalisasi ke Namespace pemilik; `package` = terlihat semua elemen dalam Package terdekat yang mengurungnya. | §7.8.24.3 | TERVERIFIKASI — OMG UML 2.5.1 |
| CL-09 | Notasi Property (atribut): `[<visibility>] [/] <nama> [: <tipe>] [[<multiplisitas>]] [= <default>] [{<modifier>}...]` dengan `<visibility>` ∈ `+` `-` `#` `~` (public, private, protected, package). `/` = derived. Bila multiplisitas dihilangkan, artinya tepat 1. | §9.5.4 | TERVERIFIKASI — OMG UML 2.5.1 |
| CL-10 | Notasi Operation: `[<visibility>] <nama> ([<daftar-parameter>]) [: [<tipe-return>] [[<multiplisitas>]]] [{<properti>}]`, `<visibility>` ∈ `+` `-` `#` `~`. Bila ada Parameter return, tipe Operation = tipe Parameter return tersebut; bila tidak ada, Operation tidak punya tipe. | §9.6.4; §9.6.3.1 | TERVERIFIKASI — OMG UML 2.5.1 |
| CL-11 | Asosiasi biner normalnya digambar sebagai garis solid yang menghubungkan dua Classifier (atau satu Classifier ke dirinya sendiri — kedua ujungnya tetap distinct). Asosiasi dengan > 2 ujung HANYA dapat digambar sebagai diamond dengan garis solid ke tiap Classifier ujung. | §11.5.4 | TERVERIFIKASI — OMG UML 2.5.1 |

## 5. Activity Diagram — Decision / Merge / Fork / Join / Initial / Final / Guard

| ID | Aturan | Referensi spesifikasi | Status / Sumber |
|---|---|---|---|
| AC-01 | Guard ActivityEdge: sebuah guard adalah ValueSpecification yang dievaluasi untuk SETIAP token yang ditawarkan ke edge. Tawaran hanya boleh melewati edge bila guard bernilai true untuk token itu. Edge TANPA guard setara dengan guard yang selalu true. Guard diizinkan pada ActivityEdge mana pun (tidak hanya di DecisionNode). | §15.2.3.3 | TERVERIFIKASI — OMG UML 2.5.1 |
| AC-02 | Notasi guard: teks dalam kurung siku `[…]` di dekat ekor (tail) garis edge. | §15.2.4 | TERVERIFIKASI — OMG UML 2.5.1 |
| AC-03 | **KOREKSI PREMIS — Decision TIDAK WAJIB punya guard di tiap cabang keluar.** Spesifikasi: "If any of the outgoing edges of a DecisionNode have guards, then these are evaluated…" — guard bersifat opsional per edge; edge tanpa guard diperlakukan sebagai guard true. Yang diwajibkan spesifikasi: (a) DecisionNode punya 1–2 incoming edge dan ≥ 1 outgoing edge; (b) SETIAP token yang ditawarkan pada incoming primer PALING BANYAK melewati SATU outgoing edge (token tidak diduplikasi); (c) token tidak boleh melewati edge yang guard-nya false; (d) bila beberapa outgoing edge tidak ber-guard / ber-guard true, token melewati paling banyak satu di antaranya (bila beberapa target menerima simultan, edge yang dilalui TIDAK ditentukan spesifikasi — non-deterministik). Untuk menghindari non-determinisme, modeler **sebaiknya** ("should") mengatur agar paling banyak satu guard true per token — ini anjuran, bukan constraint. Guard khusus `else` hanya untuk DecisionNode, PALING BANYAK pada SATU outgoing edge, dan bernilai true hanya bila token tidak diterima edge keluar lainnya. | §15.3.3.6 | TERVERIFIKASI — OMG UML 2.5.1 |
| AC-04 | MergeNode: menggabungkan banyak aliran TANPA sinkronisasi. HARUS punya tepat SATU outgoing edge dan boleh banyak incoming edge. Semua token yang ditawarkan pada incoming edge ditawarkan ke outgoing edge; tidak ada sinkronisasi / penggabungan token. Merge TIDAK memilih berdasarkan guard — guard pada edge MASUK merge (bila ada) hanya berlaku sebagai guard edge biasa (AC-01), bukan sebagai kriteria pilihan merge. Notasi: simbol belah ketupat (diamond); Merge yang dipakai harus punya ≥ 2 incoming + 1 outgoing. | §15.3.3.5; §15.3.4.3 | TERVERIFIKASI — OMG UML 2.5.1 |
| AC-05 | InitialNode: titik awal eksekusi Activity. TIDAK BOLEH punya incoming ActivityEdge. Semua outgoing edge HARUS ControlFlow. Satu token kontrol ditempatkan pada tiap InitialNode saat Activity mulai dieksekusi. Activity BOLEH punya lebih dari satu InitialNode → tiap InitialNode memulai satu aliran kontrol konkuren. Notasi: lingkaran solid. | §15.3.3.1; §15.3.4.1 | TERVERIFIKASI — OMG UML 2.5.1 |
| AC-06 | FinalNode: TIDAK BOLEH punya outgoing ActivityEdge. Dua jenis: `FlowFinalNode` = mengakhiri SATU aliran saja (token yang diterimanya dihancurkan; aliran lain tidak terpengaruh). `ActivityFinalNode` = menghentikan SEMUA aliran dalam Activity; token pertama yang mencapainya mengakhiri eksekusi Activity. Notasi: ActivityFinal = lingkaran solid di dalam lingkaran hollow ("bull's eye"); FlowFinal = lingkaran berisi tanda X. | §15.3.3.2; §15.3.4.1 | TERVERIFIKASI — OMG UML 2.5.1 |
| AC-07 | ForkNode: memecah SATU aliran menjadi banyak aliran konkuren. HARUS punya tepat SATU incoming edge dan boleh banyak outgoing edge. Token ditawarkan ke SEMUA outgoing edge; tiap penerima mendapat SALINAN token. Bila incoming = ControlFlow maka semua outgoing = ControlFlow; bila incoming = ObjectFlow maka semua outgoing = ObjectFlow. Notasi: segmen garis (bar). PERINGATAN spesifikasi: bila guard dipakai pada edge keluar ForkNode, modeler harus memastikan tidak ada JoinNode hilir yang bergantung pada kedatangan token lewat edge ber-guard itu; bila tidak dapat dihindari, sisipkan DecisionNode antara ForkNode dan edge ber-guard. | §15.3.3.3; §15.3.4.2 | TERVERIFIKASI — OMG UML 2.5.1 |
| AC-08 | JoinNode: mensinkronkan banyak aliran. HARUS punya tepat SATU outgoing edge dan boleh banyak incoming edge. Tanpa `joinSpec`, default = operator Boolean "and": token harus ditawarkan pada SETIAP incoming edge (semua cabang masuk harus tiba) sebelum token dikeluarkan. `joinSpec` eksplisit dinotasikan `{joinSpec = <value-specification>}` di dekat simbol JoinNode. Bila ada incoming ObjectFlow, outgoing HARUS ObjectFlow; bila tidak, outgoing = ControlFlow. Notasi: segmen garis (bar), sama seperti ForkNode — dibedakan dari jumlah incoming/outgoing. | §15.3.3.4; §15.3.4.2 | TERVERIFIKASI — OMG UML 2.5.1 |
| AC-09 | Simbol gabungan: satu simbol diamond yang sama dapat dipakai untuk Merge + Decision (modelnya = MergeNode dengan semua incoming edge + satu edge ke DecisionNode dengan semua outgoing edge; paling banyak satu incoming boleh dianotasi `decisionInputFlow`). Satu simbol bar yang sama dapat dipakai untuk Join + Fork (modelnya = JoinNode + satu edge ke ForkNode). Audit harus memodelkan simbol gabungan sebagai DUA node, bukan satu. | §15.3.4.3; §15.3.4.2 | TERVERIFIKASI — OMG UML 2.5.1 |
| AC-10 | Token tidak boleh "beristirahat" di ControlNode — ControlNode hanya mengatur aliran token — dengan pengecualian InitialNode dan ForkNode (yang dapat menahan token bila tawaran terblokir). | §15.2.3.2 (dan §15.3.3.1, §15.3.3.3) | TERVERIFIKASI — OMG UML 2.5.1 |
| AC-11 | DecisionNode: bila incoming primer = ControlFlow, semua outgoing HARUS ControlFlow; bila incoming primer = ObjectFlow, semua outgoing HARUS ObjectFlow. Bila DecisionNode punya 2 incoming edge, satu HARUS diidentifikasi sebagai `decisionInputFlow`, yang lain = incoming primer. `decisionInput` (bila ada) harus Behavior dengan satu Parameter return dan tanpa Parameter output lain, dan tidak boleh punya efek samping. | §15.3.3.6; §15.7.12 | TERVERIFIKASI — OMG UML 2.5.1 |
| AC-12 | Edge keluar DecisionNode yang ber-guard dievaluasi per token; urutan evaluasi guard TIDAK didefinisikan dan boleh dievaluasi secara konkuren. Token yang ditawarkan pada incoming primer tidak boleh melewati edge yang guard-nya false. | §15.3.3.6 | TERVERIFIKASI — OMG UML 2.5.1 |
